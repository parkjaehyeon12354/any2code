# 3. 시스템 구성 및 아키텍처

## 3.1 전체 구성

Ans2Quest는 **서버리스 3계층 구조**로, 별도의 상시 가동 서버 없이
Azure Static Web Apps 한 서비스 위에서 프런트엔드·백엔드·데이터가 함께 동작합니다.

```
┌──────────────────────────────────────────────────────────────┐
│                        사용자 (브라우저)                        │
└───────────────────────────┬──────────────────────────────────┘
                            │ HTTPS
┌───────────────────────────▼──────────────────────────────────┐
│              Azure Static Web Apps (전역 CDN 배포)              │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  [1] 프레젠테이션 계층 — 정적 자산                        │  │
│  │      · 시뮬레이션 21종 (HTML5 Canvas + 순수 JS)          │  │
│  │      · 공용 모듈 (theme / session / nav / research)      │  │
│  │      · 빌드 도구 없음 — 소스가 곧 배포본                  │  │
│  └────────────────────────────────────────────────────────┘  │
│                            │ fetch (/api/*)                  │
│  ┌─────────────────────────▼──────────────────────────────┐  │
│  │  [2] 애플리케이션 계층 — Azure Functions (Node.js 22)     │  │
│  │      auth · posts · profile · reports · admin · llmChat  │  │
│  │      HTTP 트리거 6종 / REST 엔드포인트 30개                │  │
│  └─────────────────────────┬──────────────────────────────┘  │
└────────────────────────────┼─────────────────────────────────┘
                             │
        ┌────────────────────┼────────────────────┐
        ▼                    ▼                    ▼
┌───────────────┐  ┌──────────────────┐  ┌────────────────────┐
│ [3] 데이터 계층 │  │  OAuth 2.0 공급자  │  │   생성형 AI (LLM)   │
│  Azure Cosmos │  │  Google · Kakao   │  │  Upstage Solar Pro4 │
│  DB (NoSQL)   │  │  GitHub · Discord │  │  (OpenAI 호환 API)  │
└───────────────┘  └──────────────────┘  └────────────────────┘
```

## 3.2 계층별 설계와 선택 근거

### [1] 프레젠테이션 계층 — 프레임워크 없는 정적 웹

React·Vue 등의 SPA 프레임워크와 번들러를 **의도적으로 배제**했습니다.

| 항목 | 선택 | 근거 |
|---|---|---|
| 렌더링 | HTML5 Canvas 2D + 순수 JavaScript | 물리 시뮬레이션은 매 프레임 좌표를 다시 계산합니다. 가상 DOM 비교 과정이 오히려 부담이 되어, Canvas에 직접 그리는 편이 60fps 유지에 유리합니다. |
| 빌드 | 없음 (No-build) | 소스 파일이 그대로 배포됩니다. 학교 환경의 저사양 PC·구형 브라우저에서도 번들 해석 없이 즉시 실행되며, 교사·학생이 소스를 열어 학습 자료로 활용할 수 있습니다. |
| 상태 공유 | URL 쿼리 파라미터 | 시뮬레이션 조건이 주소에 담기므로, 교사가 특정 실험 상태를 링크 하나로 학생에게 전달할 수 있습니다. |

공용 모듈은 `assets/js/`에 두어 21개 시뮬레이션이 함께 사용합니다.
특히 `theme.js`는 화면이 그려지기 전 `<head>`에서 실행되어 다크 모드 전환 시
화면이 번쩍이는 현상을 방지하며, Canvas는 CSS를 직접 적용받지 못하므로
`GraphTheme.palette()`가 CSS 변수 값을 읽어 그래프 색상으로 전달합니다.

### [2] 애플리케이션 계층 — Azure Functions

HTTP 트리거 기반 함수 6개로 도메인을 분리했습니다.

| 함수 | 담당 | 주요 엔드포인트 |
|---|---|---|
| `auth.js` | 소셜 로그인·세션 | `/api/auth/{provider}/start`, `/callback`, `/logout` |
| `posts.js` | 질문·답변·투표 | `/api/posts`, `/posts/{id}/comments`, `/vote` |
| `profile.js` | 프로필·약관 동의 | `/api/profile`, `/profile/terms`, `/me` |
| `reports.js` | 신고 접수 | `/api/reports`, `/api/appeals` |
| `admin.js` | 운영·제재·크레딧 | `/api/moderation/*` (8종) |
| `llmChat.js` | AI 과학 도우미 | `/api/llm/chat` |

공통 로직은 `src/lib/`로 분리했습니다 —
`session`(서명·검증), `db`(Cosmos 연결), `credit`(사용량 관리),
`sanction`(제재), `lockdown`(긴급 차단), `providers`(OAuth 정의).

**서버리스를 택한 이유**: 수업 시간에 접속이 몰리고 그 외에는 유휴 상태인
교육 서비스 특성상, 요청 단위 과금과 자동 확장이 적합합니다.
상시 가동 서버 대비 운영 비용과 관리 부담이 모두 낮습니다.

### [3] 데이터 계층 — Azure Cosmos DB

단일 컨테이너에 `type` 필드로 문서 종류를 구분하는 **단일 테이블 설계**를
적용했습니다. 컨테이너 수에 비례하는 고정 비용을 피하기 위한 선택입니다.

설계 시 확인한 제약과 대응:

- Cosmos DB에서 문서의 신원은 `(파티션키, id)` 조합입니다. 따라서 한 사용자에게
  여러 종류의 문서가 생길 경우 id에 타입 접두사를 붙여 구분합니다
  (예: `user:<sub>`, `credit:<sub>`). 그렇지 않으면 서로 다른 종류의 문서가
  같은 신원을 갖게 되어 덮어써집니다.
- 모든 조회에 `type` 필터를 적용하며, 종류가 섞인 상태에서는 정렬을 수행하지
  않습니다.

## 3.3 인증 및 보안 설계

### 소셜 로그인 (OAuth 2.0)

Google·Kakao·GitHub·Discord 4종을 지원합니다.
비밀번호를 직접 보관하지 않아 유출 위험이 원천적으로 없으며,
학생이 이미 사용 중인 계정으로 가입 절차 없이 참여할 수 있습니다.

### 세션 관리

JWT 라이브러리 대신 **HMAC-SHA256 서명 쿠키**를 직접 구현했습니다.
의존성을 추가하지 않으면서 필요한 보안 요건을 충족합니다.

| 조치 | 목적 |
|---|---|
| `crypto.timingSafeEqual` 로 서명 비교 | 일반 비교(`===`)는 불일치 지점에서 즉시 종료되어 응답 시간 차이로 서명을 추측당할 수 있습니다 (타이밍 공격) |
| `httpOnly: true` | JavaScript가 쿠키를 읽지 못하게 하여, XSS가 발생해도 세션이 탈취되지 않습니다 |
| `secure: true` | HTTPS 연결에서만 전송 |
| `sameSite: 'Lax'` | CSRF 완화 |

### 전송 계층 보안 헤더

`staticwebapp.config.json`에서 전역 적용합니다.

- **CSP** `default-src 'self'` — 외부 스크립트 실행 차단
- **X-Frame-Options: DENY** — 클릭재킹 방지
- **X-Content-Type-Options: nosniff** — MIME 스니핑 차단
- **Referrer-Policy**, **Permissions-Policy**, **COOP/CORP** 적용

## 3.4 생성형 AI 연동

AI 과학 도우미는 Upstage **Solar Pro4** 모델을 사용합니다.
OpenAI 호환 엔드포인트이므로 `openai` 패키지에서 `baseURL`만 교체하여
연동했고, 별도 SDK 의존성이 늘지 않았습니다.

교육 서비스에 AI를 넣을 때 필요한 방어 장치를 함께 구현했습니다.

1. **프롬프트 인젝션 대응 (2단계)**
   - *완화*: 입력을 정제하여 조용히 통과시킵니다. 호기심에 시험해 본 학생을
     차단하지 않기 위함입니다.
   - *탐지*: 명백한 공격 의도는 별도로 식별해 차단하며, 소명 절차를 통해서만
     해제됩니다.
2. **길이 상한** — 인젝션은 주로 장문의 지시문으로 시스템 프롬프트를
   밀어내려 시도하므로, 질문 길이를 제한합니다.
3. **크레딧 제도** — 토큰 사용량을 크레딧으로 환산해 사용자별로 차감하고
   주기적으로 충전합니다. 비용 폭증과 남용을 동시에 억제합니다.

## 3.5 배포 파이프라인 (CI/CD)

```
로컬 개발 → git push (main) → GitHub Actions → Azure Static Web Apps
                                    │
                              node --test (테스트 304개)
                                    │
                              정적 자산 + Functions 동시 배포
```

`main` 브랜치에 푸시하면 GitHub Actions가 자동으로 빌드·배포하며,
평균 약 1분 40초 내에 반영됩니다. 정적 파일과 백엔드 함수가 함께 배포되어
프런트와 API 버전이 어긋나지 않습니다.

**테스트 304개**가 저장소에 포함되어 있으며, 물리·화학 계산식의 정확성
(반트호프 식, 네른스트 식, 로트카-볼테라 모델 등)과 UI 일관성을 함께 검증합니다.
테스트 작성 시에는 **역검증**을 수행합니다 — 코드를 의도적으로 되돌려
해당 테스트가 실제로 실패하는지 확인한 뒤 원복하며, 이를 통해
'통과하지만 아무것도 검사하지 않는 테스트'를 배제합니다.
