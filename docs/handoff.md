### A. 화학 시뮬레이션 네 개 — 화학 칸이 다 찼다

**물리·화학·지구과학이 모두 찼습니다**(5·6·4개). 이번에도 설계를 Solar 4 Pro 가
잡고 구현·검증을 Claude 가 했습니다.

**화학 반응** (`chemical-reaction.html`) — "평형에 도달하면 반응이 멈춘다"를
겨냥합니다. 농도 그래프는 평평해지는데 **전환 횟수 카운터는 계속 올라갑니다.**
"순 변화는 0, 개별 전환은 계속"을 나란히 두는 구성은 Solar 제안입니다.
촉매를 1~8배로 올려도 **평형 상수 K=2.000, 평형 농도 0.1667 이 그대로**이고
도달 시간만 빨라집니다.

**산과 염기** (`acid-base.html`) — "희석하면 pH 가 계속 올라간다"를 겨냥합니다.
1억 배까지 희석 슬라이더를 열었습니다. 10⁷배에서 **물 무시 계산은 pH 8.00,
실제는 6.98** 로 갈라집니다. 온도를 올리면 중성 pH 자체가 내려가(60°C 에서 6.51)
"pH 7 = 중성"이 25°C 한정임도 함께 보입니다.

**전기화학** (`electrochemistry.html`) — "전극을 키우면 전압이 세진다"를
겨냥합니다. 전극을 0.5~5배로 바꿔도 **전압 퍼짐이 0.0000 mV** 입니다. 반대로
같은 금속·같은 용액이라 E°=0 인데 **농도차만으로 29.6 mV** 가 나옵니다.

**방사능** (`radioactivity.html`) — "반감기 두 번이면 다 없어진다"와 "원자는
수명이 정해져 있다"를 겨냥합니다. 2회 지나도 **24.9%** 가 남습니다. 원자 수를
20개로 줄이면 이론과 **11.1%p** 어긋나고, 2000개면 **0.7%p** 로 붙습니다 —
큰 수의 법칙이 눈에 보입니다.

**MoA 로 잡은 것 —** Solar 검증값을 전부 직접 계산해 대조했습니다.
산과 염기에서 **희석 상한 10⁴배 제안이 오개념을 못 깬다**는 것을 계산으로 보여
10⁸배로 늘렸고(10⁴배에서는 두 식이 소수 4자리까지 동일), 방사능·전기화학
값들은 전부 정확했습니다. Kw(60°C)=9.6e-14 도 문헌 pKw 13.017 과 일치했습니다.

**⚠ 구현하며 잡은 것 —** 새 페이지 네 개가 **옛 헤더를 복사해 와서** 물리
세 개가 `준비중` 인 채로 배포될 뻔했습니다. 드롭다운을 고치니 이번엔 **모바일
메뉴**가 어긋났습니다. 둘 다 네비 일관성 검사가 잡았습니다.

### B. 물리 시뮬레이션 세 개 — Solar 4 Pro 와 나눠서 만들었다

**물리와 지구과학 칸이 모두 찼습니다**(각 5개, 4개). 이번에는 설계를 Solar 4 Pro 가

**빛과 파동** (`wave-interference.html`) — "굴절률이 다르면 꺾인다"를 겨냥합니다.
입사각을 0°로 내리면 속도는 분명히 달라지는데도 **전혀 꺾이지 않습니다**. 파면 전체가
동시에 경계에 닿아 똑같이 느려지므로 회전할 이유가 없기 때문입니다.
n₁ &gt; n₂ 로 두면 전반사도 볼 수 있습니다(물→공기 임계각 48.75°).

**천체의 운동** (`orbital-motion.html`) — "위성은 우주에 떠 있다"를 겨냥합니다.
**중력 끄기** 버튼을 누르면 위성이 멈추는 게 아니라 속도 방향으로 곧장 날아갑니다.
숨은 주인공은 면적속도입니다 — **중력을 꺼도 31,567 km²/s 그대로**입니다.
케플러 2법칙이 중력이 아니라 각운동량 보존의 결과이기 때문입니다.

**열과 통계** (`thermal-gas.html`) — "같은 온도면 같은 속도"를 겨냥합니다.
같은 300K 에서 헬륨 1,368m/s, 산소 484m/s 로 **2.83배** 차이입니다. 온도는 속도가
아니라 에너지의 눈금이라 ½mv² 이 같으려면 가벼운 쪽이 빨라야 합니다.

**MoA 로 얻은 것 —** Solar 가 검증값을 숫자로 내놓으면 제가 전부 직접 계산해
대조했습니다. 핵심 값 30여 건은 정확했고, **오류 두 건을 잡았습니다**:
"중력을 끄면 각속도 0"(직선 운동해도 원점 기준 각도는 변합니다),
"평균 속력 1367 m/s"(공식은 v_avg 로 써놓고 숫자는 v_rms 로 계산했습니다).
지적하니 둘 다 인정했고, 첫 번째를 파다가 **"중력을 꺼도 면적속도는 일정"** 이라는
더 좋은 소재를 함께 찾았습니다. 모델이 준 숫자는 그대로 믿지 말고 반드시 검산할 것.

### D. 답변 수정·삭제를 붙였다 (`44906b0`, `60655d5`)

`progress.md` 의 남은 일 1번이었습니다. 답변은 작성만 되고 고칠 수도 지울 수도
없었습니다.

```
PATCH  /api/posts/{postId}/comments/{commentId}   수정
DELETE /api/posts/{postId}/comments/{commentId}   삭제
```

라우트에 `{postId}`/`{commentId}` 두 개가 들어갑니다. 기존 댓글 라우트는
`posts/{id}/comments` 라 `request.params.id` 를 쓰는데, 새 두 개는 이름이 다르니
**`params.id` 로 읽으면 `undefined` 가 됩니다.**

**판단한 것 —**

**삭제해도 문서를 지우지 않습니다.** `status: 'deleted'` 로 바꾸고 본문만 덮어
씁니다. 이 저장소의 기존 규칙(보류·차단도 문서를 남긴다)과 같습니다. 신고가
들어온 답변을 사용자가 지워서 증거를 없애는 것도 막힙니다.

**보류(`held`)된 답변은 수정할 수 있게 뒀습니다.** 금칙어 오탐으로 묶인 사람이
스스로 문장을 고쳐 풀려날 수 있어야 합니다. 고친 내용에 금칙어가 없으면 그
자리에서 `public` 로 돌아옵니다. 반대로 `blocked`(관리자가 막은 것)와
`deleted` 는 수정할 수 없습니다 — 그걸 열어주면 제재를 우회하는 길이 됩니다.

**답변 수(`answers`)는 공개 상태의 개수입니다.** 그래서 수정으로 상태가 바뀌면
같이 움직여야 합니다: `public→held` 는 −1, `held→public` 은 +1, 상태가 그대로면
건드리지 않습니다.

**⚠ 여기서 실제로 한 번 틀렸습니다.** 답변 수를 조정하는 판단을 `patch` **뒤에**
뒀더니, 그 시점엔 `comment.status` 가 이미 새 값이라 두 분기가 모두 거짓이 되어
**답변 수가 한 번도 안 움직였습니다.** 예외도 없고 응답도 200 이라 화면만 틀립니다.
`patch` 앞에서 `prevStatus` 로 복사해 두는 것으로 고쳤습니다.
**읽은 값으로 판단할 거면 쓰기 전에 복사하세요.**

**화면에서 겪은 것 —**

**수정 폼을 `render()` 밖에서 만들면 안 됩니다.** 처음에 수정 버튼 핸들러 안에서
폼을 만들고 거기에 `addEventListener` 를 직접 붙였는데, `render()` 가 DOM 을 통째로
다시 그리는 구조라 **수정할 때마다 리스너가 쌓입니다.** 두 번째 수정부터 저장
한 번에 PATCH 가 여러 번 나갑니다. 폼도 `answersHtml()` 이 그리고(`editing` 상태를
보고), 리스너는 `box` 하나에만 위임으로 붙여 구조적으로 막았습니다.

**삭제한 답변은 화면 목록에서도 빼야 합니다.** 서버의 댓글 목록 쿼리는
`status = 'public'` 만 주므로 새로고침하면 그 줄이 사라집니다. 화면에
"(삭제된 답변입니다)" 를 남겨두면 **새로고침하는 순간 화면이 달라집니다.**

**안 고치고 저장을 누르면 요청을 보내지 않습니다.** 보내면 `updatedAt` 만 갱신되어
"수정됨" 이 붙는데, 고치지 않았는데 고쳤다고 표시하는 건 거짓말입니다.

**수정 실패 시 폼을 닫지 않습니다.** 닫으면 사용자가 쓴 내용이 날아갑니다.

**`.sr-only` 는 이 저장소에 없습니다.** 입력칸 라벨을 `<label class="sr-only">` 로
달았다가 "답변 수정" 글자가 화면에 그대로 보였습니다. `aria-label` 로 바꿨습니다.

**⚠⚠ 테스트 234개가 전부 초록인데 라이브에서는 503 이었습니다 (`60655d5`).**

**Cosmos 의 patch 는 대상 필드가 있는지 따집니다.**

| 연산 | 규칙 |
|---|---|
| `set` | 있으면 바꾸고 없으면 만든다 (upsert) |
| `replace` | **이미 있는 필드에만** — 없으면 요청 전체 실패 |
| `remove` | **있는 필드만** — 없으면 요청 전체 실패 |
| `add` | 새 필드를 만든다 |

그게 자연스럽다고 봤다. 영구 지급이 필요해지면 별도 필드를 둬야 한다.

우회 경로를 막았다 —

설계에서 판단한 것 —

**동의를 boolean 이 아니라 시각(`termsAcceptedAt`)으로 남겼다.** 약관이 바뀌면
그 시점보다 앞선 동의는 다시 받아야 하는데, boolean 이면 그 판단을 할 수 없다.

**`PUT /profile` 을 재사용하지 않고 `POST /api/profile/terms` 를 따로 뒀다.**
`save()` 는 이름 변경에 1분 제한을 거는데, 가입 첫 화면의 이름 입력은 '변경' 이
아니라 최초 입력이라 그 제한에 걸리면 가입 자체가 막힌다. `save()` 는 옛 글의
작성자명도 갱신하는데 가입 시점엔 글이 없다.

**DB 조회가 실패하면 통과시킨다.** 멀쩡한 기존 사용자를 DB 가 흔들린다고 가입
화면에 가둘 이유는 없다.

기존 테스트 하나가 깨졌다 — 콜백 검사가 `Location: stateTarget(...)` 이라는
**대입 형태**를 보고 있었는데, 경로를 변수로 받아 감싸도록 바뀌면서 걸렸다.
확인할 것은 형태가 아니라 "경로가 `stateTarget` 에서 나오는가" 라 그렇게 고쳤다.

## 이어서 할 때 알아야 할 것

### 배포

`main`에 push하면 GitHub Actions가 바로 배포합니다. **스테이징 없습니다.**
테스트가 게이트라 빨간 테스트는 배포를 막습니다.

- **`gh` CLI가 설치돼 있습니다.** 배포 상태는 이걸로 봅니다:

```bash
gh run list --limit 3          # 최근 배포
gh run watch <id> --exit-status # 끝날 때까지 지켜보기
```

  공개 REST API(`curl`)도 여전히 됩니다. 다만 `WebFetch`는 URL당 15분 캐시라
  폴링에 쓰면 **끝난 배포가 이전 결과로 나옵니다.** 폴링은 `gh` 나 `curl` 로 하세요.

**루트에서 `npm install`을 하지 마세요.** 의존성은 `api/` 안에서만 설치합니다.
`.gitignore`가 커밋은 막아주지만 로컬에 잔재가 남습니다.

### 검증

**화면을 보지 않으면 못 잡는 버그가 이 프로젝트의 주력 버그입니다.** 지난 라운드에
잡은 5개 전부 API는 정상 응답했고 테스트도 초록이었습니다.

로컬은 `.claude/launch.json`의 **`any2code`** 항목(`npx serve`, 5500)으로 띄웁니다.
정적 서버라 `/api/*`는 전부 404입니다 — 콘솔의 `api/me` 404는 정상이니 무시하세요.
API 동작과 rewrite 규칙은 **도메인으로** 확인합니다. 같은 파일의 `vite` 항목은 루트
React 프로젝트용이라 `any2code`를 못 띄웁니다.

측정할 때 `.mega-col a`처럼 `transition`이 걸린 요소는 테마를 바꾼 직후
`getComputedStyle`이 **전환 중간값**을 돌려줍니다. 밝은 모드 대비가 2.66:1로 나와서
한 번 속았습니다. `*{transition:none!important}`를 넣고 재세요.

숫자 검사가 헛돈 사례도 있었습니다 — `el.getClientRects().length`는 블록 요소면 항상
1이고, 다크 CSS 블록을 찾던 정규식은 닫는 `}`가 들여쓰기돼 있어 **빈 문자열을 검사**하고
있었습니다. 검사를 쓰면 **버그를 다시 넣어 빨개지는지 확인**하세요.

### 밟으면 아픈 것들

- **루트에 `package.json` / `package-lock.json`을 만들지 마세요** — Oryx가 Node 앱으로
  오인해 배포가 깨집니다. 빌드 스크립트를 넣어 "고치는" 것도 답이 아닙니다. 빌드할 게
  없는 프로젝트입니다
- **`skip_app_build: true`를 켜지 마세요** — 위 사고의 2차 원인
- **`admin/`은 Functions 예약 접두사** — 등록이 조용히 거부되고 로그에도 안 남습니다.
  이 프로젝트는 `moderation/`을 씁니다
- **Cosmos 신원은 `(pk, id)`** — 같은 쌍이면 같은 문서라 `upsert`가 남의 문서를
  조용히 지웁니다. `user`는 반드시 `user:` 접두사를 유지해야 합니다
- **혼합 타입에 `ORDER BY` 금지** — 정렬 필드가 없는 문서가 통째로 사라집니다
- **HTML에 캐시 헤더가 없습니다** — 배포 직후 "안 고쳐졌다" 싶으면 이걸 먼저 의심하고
  `?cachebust=<sha>`로 확인하세요
- **줄바꿈은 LF 고정** — `.gitattributes` 가 `* text=auto eol=lf` 로 잡아둡니다. Windows
  에디터가 CRLF 로 저장해도 커밋은 LF 로 들어갑니다. 손댄 적 없는 파일이 `git status`
  에 무더기로 뜨면 `git diff --ignore-all-space --stat` 로 먼저 확인하세요 — 비어 있으면
  내용 변경 0 입니다
- **영구 제재는 `until = 9999-12-31`** — 별도 플래그가 아니라 날짜로 표현합니다.
  제재를 화면에 그리는 코드를 새로 쓸 때 `until` 을 그대로 찍으면 "9999-12-31 해제"
  가 나갑니다. `permanent` 를 먼저 보고 분기하세요. `days` 도 null 이라
  `days + '일'` 은 "null일" 이 됩니다
- **LLM 모델 교체 시 `reasoning_tokens` 확인** — thinking 계열은 `max_tokens` 예산을
  사고 토큰이 먼저 먹어서 답변이 **빈 문자열**로 옵니다. 에러가 아니라 조용히 깨집니다
- **모델 리뷰 결과는 반드시 직접 계산해 확인하세요** — 이번에 Solar 지적 3건이
  오탐이었습니다. 특히 "공식이 틀렸다" 는 지적은 값을 직접 넣어 보면 금방 갈립니다.
  반대로 오퍼스가 잡은 "설명과 그림이 어긋난다" 는 실제 버그였습니다.
- **시뮬레이션은 계산이 맞아도 화면이 틀릴 수 있습니다** — 해양판끼리 수렴에서
  `landform()` 은 "해구+호상열도" 를 반환하는데 `drawConvergent()` 는 대륙충돌을
  그리고 있었습니다. **판정 함수와 그리는 함수를 함께 검사**하세요.
- **시뮬레이션을 새로 만들 때는 기존 것을 복사하세요** — 빌드 도구가 없어 헤더·네비·
  모바일 메뉴를 매번 복사해야 합니다. **한 곳에서만** 복사하지 않으면 페이지마다
  헤더가 갈라집니다. 무대는 `--stage-bg`(항상 어두움), 캔버스는 흰 계열로 그립니다 —
  캔버스 색을 토큰에서 읽으면 다크/라이트에서 대비가 뒤집혀 한쪽이 안 보입니다.
- **물리를 그대로 쓰면 학습용으로 안 될 때가 있습니다** — 화학 결합에서 실제로 겪었습니다.
  힘이 물리적으로는 맞는데 너무 작아 아무 일도 안 일어나거나(r₀의 3배에서 0.0001),
  반대로 시간 배율을 키우면 반발항 `r^13` 이 폭발해 발산합니다. 범위를 좁히고 힘에
  상한을 두세요. **비례 관계는 유지하되 규모만 조정**하는 것이 요령입니다.
- **가입은 로그인만으로 끝나지 않습니다** — 약관 동의(`termsAcceptedAt`)까지
  받아야 합니다. 새 페이지를 만들 때 `nav-user.js` 를 반드시 읽으세요. 그게
  미동의 사용자를 `/welcome` 으로 되돌립니다. 안 읽으면 그 페이지만 절차를
  건너뛸 수 있는 구멍이 됩니다.
- **사용자당 하나뿐인 문서는 `id` 에 타입 접두사를 붙이세요** — Cosmos 는
  `(id, partitionKey)` 로 문서를 구분합니다. 제재 문서가 `id: sub, pk: sub` 을
  쓰므로, 새 타입이 같은 값을 쓰면 두 문서가 같은 자리를 다투며 서로를 덮습니다.
  크레딧에서 실제로 났고, **제재 이력이 있는 계정만 실패해서** 원인이 한참 늦게
  드러났습니다. `profile.js` 의 `'user:' + sub` 가 올바른 예입니다.
- **크레딧·제재 문서는 `patch` 가 아니라 `upsert`** — 기능을 붙이기 전에 만들어진
  문서에는 새 필드(`period` 등)가 없어서 `set /필드` 가 실패합니다
- **크레딧 초기화는 한국 시간 기준입니다** — Azure Functions 는 UTC 로 돕니다.
  `credit.js` 의 `currentPeriod()` 가 KST 보정을 합니다. 빼먹으면 한국 오전 9시에
  초기화됩니다.

  ⚠ **이 버그는 어설픈 테스트로 안 잡힙니다.** KST 오프셋 9시간이 초기화 주기
  3시간의 배수라, 보정을 통째로 지워도 "경계에서 값이 바뀌는가" 검사는 전부
  통과합니다. 실제로 그렇게 짰다가 역검증에서 드러났습니다. 구간 경계의 **실제
  시각**을 한국 시간으로 읽어 0·3·6·…·21시 정각인지 확인해야 합니다
- **카카오는 이메일을 못 받습니다** — 비즈 앱이 아니라 `account_email` 권한이
  없습니다. scope 에 넣으면 인가 요청 자체가 거부되어 **버튼을 눌러도 아무 반응이
  없는 것처럼** 실패합니다. 이메일이 `null` 이라 카카오 계정은 관리자가 될 수
  없습니다 — 관리자 작업은 구글 계정으로 하세요
- **`--surface` 와 `--line` 은 존재하지 않는 토큰입니다** — `styles.css` 에 정의된
  적이 없어서 `var(--surface, #fff)` 의 폴백이 항상 쓰입니다. 그래서 다크에서도
  카드가 흰색으로 남습니다. 실제 토큰은 `--surface-soft` / `--hairline` 입니다
- **다크에서 `--primary` 는 흰색(`#f2f2f2`)입니다** — 큰 면을 채우면 눈이 부십니다.
  말풍선처럼 넓은 곳은 화면 전용 변수로 덮어쓰세요(`--primary` 를 고치면 사이트
  전체 버튼이 바뀝니다). 그때 `--surface-dark-elevated` 는 쓰지 마세요 — 다크에서
  그 값(`#1b1b1b`)이 카드 배경과 **똑같아** 말풍선이 묻힙니다. `--hairline` 을 쓰세요
- **AI 답변에 KaTeX 를 붙일 수 없습니다** — CSP 가 `script-src 'self'` 라 CDN 이
  막힙니다. `llm.js` 가 유니코드로 직접 변환합니다. CSP 를 풀지 마세요
- **한국어 조사** — `항소`→`소명` 같은 일괄 치환은 받침이 달라져서 `소명를/가/와/는/로`가
  전부 틀립니다. 지난번에 10곳을 손봤습니다
