## 이번 라운드에 한 일

### 1. 물리학 드롭다운을 `주제 → 시뮬레이션` 두 단계로

전에는 **고전 역학** 자체가 링크라 누르면 곧바로 단진자로 갔습니다. 주제와
시뮬레이션이 한 칸에 섞여 있어서, 고전 역학에 두 번째 시뮬레이션이 생기면 놓을
자리가 없었습니다. `단진자`라는 이름이 드롭다운 어디에도 안 나왔습니다.

지금 구조:

```
물리학
├─ 고전 역학       ├─ 전기와 자기      ├─ 다른 주제
│    단진자        │    전자기 유도    │    빛과 파동 · 준비 중
                                       │    천체의 운동 · 준비 중
                                       │    열과 통계 · 준비 중
```

주제는 `<p class="mega-label">` 제목이고 그 아래가 실제로 열리는 시뮬레이션입니다.
새 시뮬레이션은 해당 주제 칸에 `<a>` 한 줄만 추가하면 됩니다.

**같은 드롭다운이 5개 파일에 복제돼 있습니다** — `Index.html`, `community.html`,
`guide.html`, `post.html`, `simulation/index.html`. 하나만 고치면 페이지마다 메뉴가
달라집니다. 공통 파일로 뺄 만하지만 아직 안 했습니다.

### 2. 최윤지 작업 합치기

원격에 커밋 2개(`3e5b0ab`, `5fa669a`)가 먼저 올라와 있었습니다. **전자기 유도**
시뮬레이션 추가 + 지웠던 `simulation/index.html` 되살리기. 리베이스로 합쳤고
**되살린 목록 페이지는 지우지 않았습니다.**

합치면서 문제 3개를 고쳤습니다.

- 목록 페이지의 네비게이션만 예전 필터 링크(`?subject=chemistry`) 방식이라, 같은
  **화학** 메뉴가 어느 페이지에 있느냐에 따라 다르게 동작했습니다 → 통일
- 목록 페이지만 `theme.js` / `session.js` / `nav-user.js`를 안 읽었습니다 → 추가
- 전자기 유도에 rewrite 규칙이 없어 `.html` 없는 주소가 404였습니다 → 추가

### 3. 다크 모드 대비 버그

`.filters`와 `.simulation-card`가 배경을 `#fff`로 박아두고 글자는 `var(--ink)`를
썼습니다. 다크에서 `--ink`가 `#f2f2f2`가 되니 **흰 바탕에 흰 글자, 대비 1.06:1**.

`var(--canvas)` + hairline 테두리(사이트 카드 관례)로 바꿔서 17.00:1 / 6.76:1,
밝은 모드 15.66:1 / 5.42:1. 전부 AA 통과.

### 4. 시뮬레이션 본문이 화면 끝에 붙어 잘림

```css
/* 이랬음 — 가운데 0 이 좌우를 뜻해서 .container 의 padding: 0 24px 을 덮음 */
.sim { padding: var(--sp-xl) 0 var(--sp-section); }
```

`<main class="container sim">`이라 `.container`가 좌우 24px를 주는데, `.sim`의 단축형
가운데 값 `0`이 그걸 지웠습니다. 헤더가 `sticky`라 같이 안 밀려서 본문만 잘린 것처럼
보였습니다. 세로만 지정하도록 고치고, 무대가 넓은 페이지라 좌우를 48px로 넉넉히
줬습니다. 860px 아래에서는 24px로 되돌립니다.

**단진자와 전자기 유도 둘 다** 같은 버그였습니다 — 후자가 전자를 바탕으로 만들어졌기
때문입니다. 시뮬레이션 페이지를 새로 만들 때 그대로 옮겨갈 수 있습니다.

다크에서만 톤을 낮출지 정해야 합니다.

**2. 시뮬레이션 목록으로 가는 길.** 드롭다운을 통일하면서 `/simulation/`으로 가는

## 이어서 할 때 알아야 할 것

### 배포

`main`에 push하면 GitHub Actions가 바로 배포합니다. **스테이징 없습니다.**
테스트가 게이트라 빨간 테스트는 배포를 막습니다.

`gh` CLI가 없으니 공개 API로 확인합니다:

```bash
curl -s "https://api.github.com/repos/parkjaehyeon12354/any2code/actions/runs?per_page=1"
```

`WebFetch`는 URL당 15분 캐시라 폴링에 쓰면 **끝난 배포가 이전 결과로 나옵니다.**
`curl`을 쓰세요.

### 검증

**화면을 보지 않으면 못 잡는 버그가 이 프로젝트의 주력 버그입니다.** 이번 라운드에
잡은 5개 전부 API는 정상 응답했고 테스트도 초록이었습니다.

숫자 검사가 헛돈 사례가 3개 있었습니다 — `el.getClientRects().length`는 블록 요소면
항상 1이고, 다크 CSS 블록을 찾던 정규식은 닫는 `}`가 들여쓰기돼 있어 **빈 문자열을
검사**하고 있었습니다. 검사를 쓰면 **버그를 다시 넣어 빨개지는지 확인**하세요.

로컬 말고 **도메인으로** 열어서 확인합니다. `.claude/launch.json`의 vite 서버는
루트 React 프로젝트용이라 `any2code`를 못 띄웁니다.

### 밟으면 아픈 것들

- **`admin/`은 Functions 예약 접두사** — 등록이 조용히 거부되고 로그에도 안 남습니다.
  이 프로젝트는 `moderation/`을 씁니다
- **Cosmos 신원은 `(pk, id)`** — 같은 쌍이면 같은 문서라 `upsert`가 남의 문서를
  조용히 지웁니다. `user`는 반드시 `user:` 접두사를 유지해야 합니다
- **혼합 타입에 `ORDER BY` 금지** — 정렬 필드가 없는 문서가 통째로 사라집니다
- **HTML에 캐시 헤더가 없습니다** — 배포 직후 "안 고쳐졌다" 싶으면 이걸 먼저 의심하고
  `?cachebust=<sha>`로 확인하세요
- **한국어 조사** — `항소`→`소명` 같은 일괄 치환은 받침이 달라져서 `소명를/가/와/는/로`가
  전부 틀립니다. 지난번에 10곳을 손봤습니다
