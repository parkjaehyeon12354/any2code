## 아키텍처 결정

**컨테이너 하나에 `type`으로 구분** — Cosmos 무료 계층은 계정당 1000 RU/s인데 컨테이너마다 최소 400을 잡습니다. 넷으로 나누면 한도를 넘습니다.

**OAuth를 직접 구현** — SWA 내장 인증은 Free 플랜에서 커스텀 OIDC를 지원하지 않아 카카오를 붙일 수 없습니다. `api/`에서 authorization code 흐름을 직접 처리합니다. 지원 제공자는 Google · Kakao · Discord · GitHub 네 개이고, `/science` 의 로그인 모달은 학생 대상이라 **카카오와 구글만** 노출합니다.

**AI 크레딧은 횟수가 아니라 토큰으로 셉니다** — 같은 과학 질문인데 답변이 394 ~ 1080 토큰으로 갈렸습니다. 횟수로 세면 짧게 묻는 학생이 손해를 봅니다. 30 토큰 = 1 크레딧, 무료 200 크레딧(평균 8회), 00시 기준 3시간마다 초기화. 스케줄러 없이 문서에 적어둔 구간과 비교해 '읽을 때 판단' 합니다.

**권한은 서버에서만 판정** — `admin.html`은 누구나 열 수 있습니다. 데이터를 안 내주는 것이 유일한 방어선입니다.

**의존성 2개** (`@azure/functions`, `@azure/cosmos`) — JWT 라이브러리 없이 내장 `crypto`로 세션을 서명합니다.

**제재 이력은 집행과 분리했습니다** — 현재 제재는 사용자당 문서 하나(`upsert`)라 새 제재가 이전 것을 덮습니다. 그래서 이력은 `type: 'sanctionLog'` 문서를 이벤트마다 하나씩 쌓아 따로 남깁니다. 집행 경로(`sanction.active`/`block`)는 이 이력을 **보지 않습니다** — 이력이 집행 근거가 되면 기록 한 줄이 실패했을 때 제재가 누락되고, 반대로 지난 이력이 섞이면 이미 풀린 사람을 계속 막습니다. 같은 이유로 이력 기록이 실패해도 제재 처리는 성공으로 끝냅니다. 대안(제재 문서 id를 건별로 바꾸기)은 집행·소명·해제 경로 5곳을 모두 고쳐야 해서 택하지 않았습니다.

**사용자 문서 id는 `user:{sub}`** — 제재 문서가 이미 `id = pk = sub`를 씁니다. Cosmos 고유성이 `(pk, id)`라서 프로필 문서를 같은 규칙으로 만들면 같은 문서가 되고, **로그인하는 순간 제재가 덮여 사라집니다.** `pk`는 `sub`로 남겨 제재·소명과 같은 파티션에 모읍니다. 테스트가 이걸 막습니다.

## 시뮬레이션

계획서의 핵심 차별점입니다. 지금 두 개가 돌아갑니다.

**단진자** (`/simulation/pendulum`) — 줄 길이·처음 각도·공기 저항을 바꾸며 주기를 직접
잽니다. 교과서의 `T = 2π√(L/g)`는 각도가 작을 때만 맞는 근사식이라, 언제부터 어긋나는지
눈으로 보는 게 목적입니다.

**전자기 유도** (`/simulation/electromagnetic-induction`) — 최윤지 작업. 자석을 코일에
넣고 빼며 유도 전류를 관찰합니다.

**입자의 운동** (`/simulation/particle-motion`) — 온도·질량·용기 크기를 바꾸며 기체 입자를
관찰합니다. 입자를 하나하나 굴리고 충돌을 직접 계산해서, 맥스웰 분포가 **저절로 생기는
것**을 보여줍니다. 분포를 수식으로 그려놓고 입자를 장식으로 두면 "왜 저런 분포가
나오는가" 를 볼 수 없습니다.

같은 온도에서도 입자마다 속력이 다르다는 것이 핵심입니다 — 평균만 보고 "모두 같은 속력"
이라고 생각하기 쉬운데, 가장 빠른 입자가 가장 느린 입자보다 20배 넘게 빠릅니다.

**화학 결합** (`/simulation/chemical-bond`) — 두 원자를 당겼다 놓으면 항상 같은 자리로
돌아옵니다. 그 자리가 결합 길이입니다. 레너드-존스 퍼텐셜로 힘을 계산하며, H₂·O₂·N₂·HCl
네 조합을 고를 수 있습니다.

교과서는 퍼텐셜 곡선 그림만 보여주는데, **직접 당겨봐야** 왜 그 거리에서 멈추는지
알 수 있다고 봤습니다. 캔버스에서 드래그할 수 있게 한 이유입니다.

### 수치 적분

**반음 오일러(symplectic Euler)** 를 씁니다. 속도를 먼저 갱신하고 그 속도로 위치를 옮깁니다.

```js
const acc = -(G / params.L) * Math.sin(state.theta) - params.b * state.omega;
state.omega += acc * DT;      // 속도 먼저
state.theta += state.omega * DT;
```

보통 오일러는 진자를 돌릴수록 에너지가 커져서 진폭이 저절로 자랍니다 — 공기 저항 0으로
두고 오래 돌리면 바로 드러납니다. 순서만 바꾼 반음 오일러는 에너지가 갇혀 있어 몇 분을
돌려도 진폭이 유지됩니다. 코드 길이는 같습니다.

시간 간격은 **화면 주사율과 무관하게 1/480초 고정**입니다. `requestAnimationFrame`의
실제 간격을 그대로 쓰면 120Hz 노트북과 60Hz 모니터에서 **측정 주기가 다르게 나옵니다.**
물리량이 하드웨어에 따라 달라지면 실험이 아닙니다.

주기는 각도의 **0 교차**를 잡아 재고, 교차 지점을 선형 보간해 프레임 경계 오차를 줍니다.

**검증** — 90°에서 근사식 대비 **+18.03%** (알려진 값 ≈+18%), 5°에서 +0.047%,
줄 길이 ×4 → 주기 ×2.0000.

### 공유 링크

**공유를 누를 때만** 현재 설정을 쿼리로 만듭니다. 슬라이더를 움직일 때마다 주소가
바뀌면 뒤로 가기가 슬라이더 되감기가 됩니다.

로그인해야 만들 수 있습니다. 로그아웃 상태면 설정을 `sessionStorage`에 넣고 `/login`으로
보낸 뒤, 돌아오면 그 설정을 복원합니다 — 로그인하러 갔다 오니 다 날아가 있으면
아무도 두 번은 안 합니다.

### 생명과학 — 오개념 네 개를 겨냥했다

생명과학 네 개를 더해 마지막 칸을 채웠습니다. 넷 다 학생이 실제로 갖고 있는
오개념을 하나씩 정해 놓고, **그게 틀렸다는 걸 슬라이더로 보이게** 만들었습니다.

**개체와 생태계** (`/simulation/ecology-population`) — "천적을 없애면 번성한다"를
겨냥합니다. 순수 로트카-볼테라(번식률 `r=0.5`, 전환효율 `e=0.3`, 포식자 사망률
`m=0.08`)입니다. 포식자 피크가 주기의 0.20배만큼 피식자 피크보다 늦게 옵니다.

로지스틱 항(환경 수용력)을 넣은 설계안이 먼저 있었고 검증값 6건도 전부 정확했지만
못 썼습니다. 그 상수로 돌리니 5초 만에 피식자가 40에서 0.26으로 붕괴하고 진동이
잦아들어, **정작 보여줄 주기가 화면에서 사라졌습니다.** 숫자가 맞아도 화면이 죽으면
소용없습니다.

**신경과 자극전달** (`/simulation/neural-signal`) — "세게 누르면 신호도 세다"를
겨냥합니다. 표준 leaky integrate-and-fire(`TAU=10.0`ms, `VTH=15.0`mV,
`V_REST=-70`mV, `V_PEAK=+30`mV, `V_HYPER=-80`mV). 자극 세기를 끝까지 올려도 봉우리
높이는 고정이고, **대신 더 자주** 일어납니다.

그래서 `spikeVoltage` 는 자극 세기를 인자로 받지 않습니다. 받는 순간 "세게 누르면
크게"가 되어 겨냥한 오개념을 그대로 가르치게 됩니다. 검사가 이 서명을 지킵니다.

불응기 비교는 `refLeft > 1e-9` 여야 합니다. `> 0` 으로 두면 남은 시간이 정확히
0 이 아니라 `3.55e-15` 로 남아 시간이 0 만큼만 흐르는 교착에 빠집니다
(실제로 `t=34.47` 에서 멈췄습니다).

**순환과 수송** (`/simulation/circulation-transport`) — "굵을수록 빠르다"를
겨냥합니다. 반대입니다. 연속 방정식(총 단면적 × 유속 = 일정)이라 총단면적 496배가
곧 유속 496배 차이가 됩니다. 모세혈관 하나(`CAP_R = 4e-4` cm)는 가늘어도 수십억
개(N≈3.12e9)를 합치면 대동맥보다 넓어서 **거기서 피가 가장 느립니다**(유속
0.053cm/s, 통과 1.87초). 그 느림이 산소를 넘겨주는 데 필요한 시간입니다.

**대사와 효소** (`/simulation/metabolism-enzyme`) — "온도를 올리면 계속 빨라진다"를
겨냥합니다. 화학에서는 맞지만 효소는 어느 지점부터 거꾸로 느려집니다.
미카엘리스-멘텐(`Km = 2.0` mM)에 열 변성(`T_HALF = 50`°C)을 얹어서, 55°C 속도(91.5)가
25°C(90.9)와 거의 같아집니다. 단백질이 열에 풀리기 때문입니다.

이걸로 **목록에 준비중 카드가 하나도 없습니다.** 물리 5 · 화학 6 · 생명 6 ·
지구과학 4, 스물한 개입니다.

### 세부 조작 — 어디에 붙일지부터 검증했다

시뮬 세 개에 조작 변수를 더했습니다. **어디에 붙이면 좋을지를 Solar 4 Pro 에게
물어 봤는데, 다섯 개 추천 중 둘은 쓸 수 없었습니다.** 하나는 이미 있는 기능이었고
(빛과 파동의 입사측 굴절률 — n₁·n₂ 슬라이더가 둘 다 있습니다), 하나는 구조를
통째로 다시 만들어야 했습니다. 모델이 준 목록을 그대로 믿었으면 있는 걸 또 만들
뻔했습니다.

**단진자 · 추 질량** (0.1~2.0 kg) — 주기 공식에 질량이 없다는 것을 슬라이더로
보입니다. m=0.2 와 m=2.0 둘 다 측정 주기 2.010 s (이론 2.006 s).

다만 감쇠는 다릅니다. 저항은 '힘' 이고 가속도는 힘을 질량으로 나눈 것이라,
같은 저항에서 무거운 추가 천천히 멈춥니다(`params.b / params.m`). 저항 0.3 에서
6초 뒤 진폭이 m=0.2 는 0.28°, m=2.0 은 18.71°. **주기는 질량과 무관하지만
감쇠는 관련이 있다** 는 것까지 한 화면에서 보입니다.

**전자기 유도 · 코일 단면적** (10~40 cm²) — `Φ = B·A` 라 면적에도 비례합니다.
지금까지 자석 세기·속도·감은 수만 있어서 면적은 상관없는 것처럼 읽혔습니다.
면적 4배 → 최대 기전력 3.73배(샘플링 간격 때문에 정확히 4배로는 안 찍힙니다).

**산과 염기 · 강산/약산과 pKa** (2~8) — 0.1 M 에서 강산 pH 1.00, 아세트산
(pKa 4.76) 2.88. 이온화도(1.3%)도 함께 보여줍니다.

**약산은 근사식으로 풀지 않습니다.** `[H⁺] ≈ √(Ka·C)` 는 이온화도가 작을 때만
맞습니다. pKa=2 는 이온화도가 27% 라 근사가 1.50 을 내놓는데 정확식은 1.568
입니다. 전하 균형 `[H⁺] = [A⁻] + [OH⁻]` 를 이분법으로 풉니다.

### 나머지도 훑었습니다 — 화면이 말하는 것을 만질 수 있는가

이 기준으로 여덟 개가 더 나왔습니다.

| 시뮬 | 붙인 것 | 왜 |
|---|---|---|
| 개체와 생태계 | 피식자 번식률 r | 본문이 "피식자에게 좋은 일을 해주면 정작 늘어나는 건 포식자" 라 단언 |
| 화학 반응 | 온도·반응열 | "온도를 바꾸면 K 값 자체가 달라진다 — 시험에 자주 나온다" |
| 천체의 운동 | 중심 천체 질량 GM | 지구로 고정이라 달·화성 궤도를 볼 수 없음 |
| 순환과 수송 | 모세혈관 지름 | 총단면적의 두 인자 중 개수만 조작 가능 |
| 대사와 효소 | Km | 미카엘리스-멘텐 곡선 모양이 고정 |
| 신경과 자극전달 | 역치 | 측정 패널에 "역치 −55 mV" 를 보여주면서 못 만짐 |
| 방사능 | 아이소톱 | ISO 테이블이 코드에만 있고 고를 수단이 없음 |
| 지구 계절 | 근일점 날짜 | "태양에 가장 가까운 때는 1월" 이라 해놓고 그 1월을 못 바꿈 |
| 전기화학 | 온도 | "10배 농도차 = 29.6 mV" 가 25°C 값이라는 걸 볼 수 없음 |
| 빛과 파동 | 파장 | "v = fλ 에서 f 고정" 을 설명하고 λ₂/λ₁ 비도 보여주는데 파장을 못 바꿈 |

**역치에서 한 번 틀렸습니다.** `drive = VTH·I/ITH` 로 두었더니
`t = −TAU·ln(1 − VTH/drive)` 에서 **VTH 가 약분돼 사라졌습니다.** 역치를 8 로
내리든 25 로 올리든 충전 시간이 13.86 ms 로 똑같았습니다 — 슬라이더가 아무 일도
안 한 것입니다. 자극이 만드는 탈분극은 역치와 무관해야 합니다. 고친 뒤에는
역치 20·자극 80% 에서 아예 안 터지고 자극 100% 여야 16.09 ms 에 터집니다.
봉우리는 어느 경우든 100 mV 그대로입니다.

**입자의 운동에는 넣지 않았습니다.** "입자 지름 슬라이더" 제안이 있었는데
코드를 보니 반지름이 이미 `Math.cbrt(S.mass)` 로 질량에서 나오고, 그 값을
충돌 판정에도 씁니다. 따로 두면 "무거운데 작은 입자" 가 생깁니다.
연결이 끊기면 잡도록 검사만 남겼습니다.

**모델이 준 목록은 절반이 못 쓰는 것이었습니다.** 여덟 개 추천 중 일곱을
걸렀습니다 — 종속변수(굴절률로 이미 정해지는 속력, 이슬점으로 정해지는 상대습도),
반응식을 잘못 읽은 것(A ⇌ B 는 Δn=0 이라 부피를 바꿔도 평형이 안 움직입니다),
그리고 모델 스스로 "보류" 에도 넣은 자기모순 넷. **추천은 코드와 대조해야
합니다.**

### 화면이 숫자를 보여주는데 만질 수 없으면 그게 신호였다

세 라운드에 걸쳐 스캔 방식이 바뀌었습니다. 처음에는 `const NAME = 숫자;` 만
찾았고, 그 다음에는 객체 안 상수와 매직넘버까지 봤고, 마지막에는 **각 페이지
본문이 단언하는 인과를 뽑아 조작 가능 범위와 대조**했습니다. 마지막 방식에서만
개체와 생태계·화학 반응이 나왔습니다. 앞의 둘은 그냥 지나쳤던 것들입니다.

## 개발 중 잡은 주요 버그

배포 후 실서버를 직접 찔러보지 않았으면 못 찾았을 것들입니다.

**심화 탐구가 시뮬레이션 15개 페이지에서 죽어 있었다** — 페이지는 멀쩡히 배포돼
있는데 모바일 메뉴에서는 `준비중` 이라 들어갈 수 없었고, 데스크톱에서는
`href="#"` 이라 눌러도 아무 일이 없었습니다. 심화 탐구를 만들기 전의 헤더를
복사해 쓴 파일들이 그대로 남아 있던 것입니다. **링크가 틀린 것보다 나쁩니다 —
아무 일도 안 일어나니 버그로 신고조차 되지 않습니다.** 기존 검사는 `/simulation/`
링크만 비교해서 이걸 못 봤습니다. "만들어 둔 페이지가 네비에서 죽어 있지 않은가"
를 보는 검사를 새로 넣었습니다.

**모바일 메뉴를 찾는 정규식이 틀려 30개 파일을 놓칠 뻔했다** — 생명과학 네 개를
네비에 붙이면서 `<nav class="mobile-menu">` 를 찾았는데 실제로는 `<div>` 였다.
갱신 대상 0개로 나왔고, 그대로 넘어갔으면 모바일에서 네 개 전부 접근 불가였다.
"0개 갱신"이 나오면 그게 정상인지 반드시 확인해야 한다.

**새 페이지가 옛 네비를 물고 들어왔다** — 화학 네 개를 만들 때 기존 페이지에서
헤더를 복사해 왔는데, 그 사이 물리 세 개가 추가돼 있었습니다. 새 페이지의 네비만
`준비중` 인 상태로 배포될 뻔했습니다. 페이지 사이 네비가 어긋나는지 보는 검사가
잡았습니다 — 사람 눈으로는 27개 파일의 드롭다운을 다 못 봅니다.

**모바일 메뉴는 또 따로 있었다** — 드롭다운을 고치고 통과한 줄 알았는데, 같은
검사가 이번엔 모바일 쪽을 짚었습니다. 이 저장소는 데스크톱과 모바일 네비가
별도 마크업이라 한쪽만 고치면 반드시 갈라집니다.

**미리보기 여덟 장이 전부 같은 그림이었다** — 목록의 미리보기를 JS 가 canvas 에
그리고 있었는데, 코드가 `if (단진자) {…} else {전자기 유도}` 였습니다. 시뮬레이션이
두 개일 때는 맞았지만 여덟 개로 늘자 **단진자를 뺀 일곱 장이 전부 '전자기 유도'**
가 됐습니다. HTML 은 멀쩡했고(카드마다 올바른 SVG 가 들어 있었습니다) CSS 가
`.sim-preview svg { display: none }` 로 그것을 숨긴 채 canvas 만 보여줬습니다.
**테스트도 통과했습니다** — 마크업은 정확했으니까요. 스크린샷을 눈으로 보고서야
찾았습니다. canvas 를 걷어내고 카드가 가진 SVG 를 그대로 보여주게 고쳤습니다.
**항목마다 분기하는 코드는 항목이 늘면 조용히 틀립니다.**

**만들어 놓고 목록에 안 붙인 시뮬레이션이 여섯 개 있었다** — 화학 2, 생명 2,
지구 2 가 파일도 있고 네비 드롭다운에도 있는데 **목록 카드만 '준비중'** 이었습니다.
목록으로 들어온 사용자는 만든 줄도 몰랐습니다. 링크 검사가 "링크 걸린 파일이
존재하는가" 만 봤기 때문에 반대 방향(파일이 있는데 안 걸린 것)을 놓쳤습니다.

**없는 필드에 `replace` 를 걸어 수정·삭제가 통째로 503 이었다** — 테스트 234개가
전부 초록인 채로 배포됐는데, 라이브에서 답변을 수정하면 **무조건** 503 이었습니다.

Cosmos 의 patch 는 대상 필드의 존재 여부를 따집니다. `replace` 는 **이미 있는
필드에만** 되고, `remove` 는 **없는 필드를 지우려 해도** 실패합니다. 있으면 바꾸고
없으면 만드는 건 `set` 뿐입니다. 그런데 `updatedAt`·`deletedAt` 은 처음 수정·삭제할
때 문서에 없는 필드이고, `heldWords` 는 금칙어에 걸린 적 없는 답변에 없습니다.
**정상 답변을 수정하는 순간 반드시 터지는 조합**이었습니다.

**진짜 문제는 테스트가 이걸 못 잡은 것입니다.** `test/fake-container.js` 의 가짜
`patch` 가 `set`/`replace`/`add`/`remove` 를 **전부 대입으로** 처리하고 있었습니다.
가짜가 실제보다 관대하면, 그 차이만큼이 검사되지 않는 구멍이 됩니다.
실제 규칙대로 존재 여부를 따져 던지게 고쳤고, 되돌려보니 4개(수정)와 1개(삭제)가
빨개집니다. **가짜 객체는 편한 쪽이 아니라 실제와 같은 쪽으로 맞춰야 합니다.**

**patch 한 뒤에 옛 상태를 읽고 있었다** — 답변을 수정할 때 답변 수를 올릴지
내릴지는 **고치기 전 상태**로 판단해야 하는데, 문서를 `patch` 로 바꾼 **다음에**
`comment.status` 를 봤습니다. 그 시점엔 이미 새 상태라 두 분기가 모두 거짓이 되고
답변 수가 한 번도 안 움직였습니다. 예외도 안 나고 응답도 200 이라 화면만 틀립니다.
`patch` 앞에서 `prevStatus` 로 붙잡아 두는 것으로 고쳤습니다.
**읽은 값으로 판단할 거면 쓰기 전에 복사해 둬야 합니다.**

**문서 두 개가 같은 자리를 다퉜다** — 크레딧 문서를 `id: sub, pk: sub` 로 만들었는데
제재 문서가 이미 같은 값을 쓰고 있었습니다. Cosmos 는 `(id, partitionKey)` 로 문서를
구분하므로 둘이 서로를 덮었습니다. **제재를 받은 적 있는 계정만 실패**해서 원인이
한참 늦게 드러났습니다 — 첫 진단(`patch` 문제)은 틀렸고, 고친 뒤에도 증상이 그대로라
다시 파고들어서야 찾았습니다. `credit:` 접두사로 해결했습니다.

**검사가 버그를 못 잡고 있었다** — 크레딧 3시간 초기화의 시간대 처리를 "경계에서
값이 바뀌는가" 로만 검사했습니다. 그런데 KST 오프셋 9시간이 초기화 주기 3시간의
배수라, **한국 시간 보정을 통째로 지워도 테스트가 전부 통과**했습니다. 역검증(일부러
버그를 되돌려 빨개지는지 확인)에서 드러났습니다. 구간 경계의 실제 시각을 한국
시간으로 읽어 0·3·6·…·21시 정각인지 확인하도록 고쳤습니다. **초록색 테스트가
곧 안전은 아닙니다.**

**주석이 검사를 통과시켰다** — 시뮬 세부 조작에 검사를 넣고 역검증했더니 두 건이
안 잡혔습니다. `params.area/20` 을 찾는 검사가 코드에서 그 곱셈을 빼도 초록이었는데,
바로 위 **주석에 같은 글자가 남아 있었기** 때문입니다. 문자열 매칭 검사는 코드와
주석을 구분하지 않습니다. 패턴에 구문 이웃을 붙여
(`params.strength*(params.area/20)` 처럼 식 전체, 약산은 `if (!weak) return hExact(c);`
라는 분기 자체) 고친 뒤 다시 되돌려 빨개짐을 확인했습니다. **검사를 넣었으면
반드시 되돌려 보고, 안 잡히면 패턴을 좁히세요.**

**존재하지 않는 CSS 토큰** — `var(--surface, #fff)` / `var(--line, #e5e7eb)` 를 여러 곳에서
썼는데 두 토큰은 `styles.css` 에 정의된 적이 없습니다. 폴백이 항상 쓰여서 다크
모드에서도 카드가 흰색으로 남았습니다. 실제 토큰은 `--surface-soft` / `--hairline`
입니다.

**thinking 모델이 답변을 통째로 비움** — `/science` 를 Gemini 3.7 Flash 로 붙였을 때
답변이 빈 문자열로 왔습니다. thinking 계열은 `max_tokens` 예산을 **사고 토큰이 먼저**
소비해서 `finish_reason: length` 에 `completion_tokens: 0` 이 떨어집니다. HTTP 는
200 이고 에러도 없어서 코드는 정상 동작한 것처럼 보이고, 화면에만 "AI가 빈 답변을
반환했습니다" 가 뜹니다. 응답의 `usage.completion_tokens_details.reasoning_tokens`
를 보지 않으면 원인을 못 찾습니다. **모델을 바꿀 때마다 확인해야 하는 지점입니다.**

**AI 답변의 수식이 LaTeX 원문으로 노출됨** — `llm.js` 가 답변을 `textContent` 로
꽂아서 화면에 `\(\sin\theta \approx \theta\)` 가 그대로 보였습니다. KaTeX 는 CSP
(`script-src 'self'`)가 CDN 을 막아 쓸 수 없어, 의존성 없이 유니코드로 변환합니다.
치환표에 없던 `\circ` 가 배포 후에도 새어나왔는데, 표에 항목을 더하는 방식으로는
같은 일이 반복되므로 **표에 없는 명령은 백슬래시만 떼는 안전망**을 뒀습니다.

**프롬프트 인젝션 정제 순서에 우회 경로** — `</question> system: ...` 은 태그를 먼저
지우면 `system:` 이 문장 첫머리로 올라와 검사를 그대로 통과했습니다. 역할 표지 처리를
태그 제거 **뒤로** 옮겨 막았습니다. 순서 하나로 방어가 통째로 뚫리는 부류입니다.

**`science.html` 이 `theme.js` 를 안 읽음** — 아래 '목록 페이지만' 사고와 같은
부류가 또 났습니다. 사이트는 다크인데 그 페이지만 하얗게 뜨고, 입력창 배경도 리터럴
`#fff` 라 다크에서 흰 바탕에 흰 글자가 됩니다. **새 페이지를 만들 때 `theme.js`·
`session.js`·`nav-user.js` 를 넣었는지 확인하는 것이 반복 항목이 됐습니다.**

**테스트 파일이 프로덕션에 로드됨** — `package.json`의 `main`이 글로브라 `auth.test.js`까지 진입점으로 잡혔습니다. 배포됐다면 `SESSION_SECRET`이 저장소에 적힌 공개값으로 덮여 **누구나 관리자 쿠키를 위조**할 수 있었습니다.

**`SESSION_SECRET` 에 시크릿 대신 생성 명령어가 들어가 있었음** — Azure 앱 설정 값이
`node -e "…randomBytes(32)…" | clip` 문자열 그대로였습니다. 명령을 복사해 붙여넣는
과정에서 **결과 대신 명령 자체가** 들어간 것으로 보입니다. 고정된 공개 문자열이므로
위의 `auth.test.js` 사고와 결과가 같습니다 — 아는 사람은 세션 쿠키를 위조할 수 있습니다.
64자 난수로 교체했고 그 시점의 세션은 전부 무효화됐습니다.

**환경 변수는 화면으로 확인해야 합니다.** 코드도 테스트도 이걸 못 잡습니다 — 값이
비어 있지 않으니 `is not set` 검사를 통과하고, HMAC 은 어떤 문자열로도 서명됩니다.
`az staticwebapp appsettings list -n ans2quest-rg -g ans2quest-rg` 로 눈으로 봐야 합니다.

**OAuth 콜백이 내부 호스트로 나감** — SWA는 Functions를 `*.azurewebsites.net`으로 호출합니다. 요청 URL에서 도메인을 뽑던 코드 때문에 로그인이 구조적으로 불가능했습니다.

**`admin/`은 Functions 예약 접두사** — 라우트 등록이 조용히 거부됩니다. 파일은 로드되고 로그에도 안 남아서, 배포 후 404를 보고서야 알았습니다. → `moderation/`으로 변경.

**차단된 글에 투표 가능** — 목록에서 가리기만 하고 투표 핸들러가 상태를 안 봤습니다. 나중에 오탐으로 공개하면 조작된 점수를 달고 나타납니다.

**제재 모달이 저장 성공에도 "저장되지 않았습니다"** — 실제로는 저장되고 있었는데 화면이 거짓말을 했습니다.

**목록 요약이 두 번째 글부터 `undefined`** — `posts.map(publicPost)`가 원인입니다. `map`은 콜백에 `(요소, 인덱스, 배열)`을 넘기므로 `publicPost(p, full, viewerSub)`의 `full`에 인덱스가, `viewerSub`에 배열이 들어갔습니다. 인덱스 0만 falsy라 첫 글은 멀쩡하고 나머지는 `excerpt` 대신 본문 전체가 실려 나갔습니다. `viewerSub`가 배열이 된 탓에 `mine`도 늘 `false`였습니다.

**교훈: 테스트가 글을 하나만 만들면 이 부류는 절대 안 잡힙니다.** 인덱스 0은 falsy라 통과합니다. 테스트 94개를 통과하고도 실서버 화면에 `undefined`로 드러났습니다. 지금은 3개를 만들어 전부 `excerpt`인지 확인하고, 수정을 되돌려 실제로 실패하는 것까지 확인했습니다.

**제재 없는 사용자에게 제재 배너가 보임** — `[hidden]`은 브라우저 기본값이 `display: none`인데 `.suspended`가 `display: flex`라 특정도에서 밀렸습니다. `hidden=true`인데 렌더돼서, 제재받지 않은 학생에게도 "글쓰기가 제한된 상태입니다"와 소명 버튼이 떴습니다. 클래스 하나만 고치면 같은 실수가 또 나므로 `styles.css`에 `[hidden] { display: none !important }`를 뒀습니다 — 화면 곳곳이 `el.hidden`으로 토글하고, 숨김은 어떤 클래스보다 세야 합니다.

**다크 모드에서 흰 바탕에 흰 글자** — 세 곳에서 같은 실수가 났습니다. 로그인 카드,
시뮬레이션 목록의 과목 필터와 카드가 배경을 `#fff`로 박아두고 글자는 `var(--ink)`를
썼습니다. 다크에서 `--ink`가 `#f2f2f2`로 바뀌니 대비 **1.06:1** — 글자가 그냥 없습니다.
토큰을 쓰는 화면에 리터럴 색을 하나 섞으면 밝은 모드에서는 멀쩡해 보이고 다크에서만
터집니다. 카드 배경은 `var(--canvas)` + hairline 테두리로 통일했습니다.

**시뮬레이션 본문이 화면 끝에 붙어 잘림** — `<main class="container sim">`인데 `.sim`이
`padding: var(--sp-xl) 0 var(--sp-section)` 세 값 단축형을 썼습니다. 가운데 `0`이 좌우를
뜻하므로 `.container`의 `padding: 0 24px`를 0으로 덮었습니다. 헤더가 `sticky`라 같이
밀리지 않아 본문만 잘린 것처럼 보였습니다. 단축형 대신 `padding-top`/`bottom`만 지정합니다.

**`Session.refresh()`가 `inflight`를 안 비움** — 두 번째 호출이 페이지 로드 시점의 응답을
그대로 돌려줘서, 이름을 바꿔도 네비게이션에 옛 이름이 남았습니다.

**`nav-user.js`가 갱신값을 자기 자신과 비교** — 비교 대상이 `Session.load()`였는데 새로고침
뒤에는 이미 갱신된 값이라 항상 같았습니다. 그려둔 값을 따로 들고 비교하도록 고쳤습니다.

**목록 페이지만 `theme.js`·`session.js`를 안 읽음** — 사이트는 다크인데 그 페이지만
하얗게 뜨고, 로그인해도 우측 상단이 계속 `시작하기`였습니다. 로그인이 풀린 것처럼
보이는 화면은 그 자체로 버그입니다.

**짝 없는 `package-lock.json` 하나가 배포를 네 번 깨뜨림** — 루트에서 `npm install` 을
한 번 잘못 돌리면 npm 이 `{"packages":{}}` 짜리 빈 lock 파일만 만들어 놓습니다.
`package.json` 은 없는데 lock 파일만 있는 상태입니다. Oryx 는 lock 파일만 봐도 Node
프로젝트로 판정하므로, 빌드 스크립트를 찾다가 `Could not find either 'build' or
'build:azure' node under 'scripts' in package.json` 으로 **2 초 만에** 죽었습니다.

에러 메시지가 "빌드 명령을 워크플로에 추가하라"고 안내하는 게 함정이었습니다. 이
프로젝트는 정적 HTML 이라 빌드할 게 애초에 없습니다. 안내대로 `skip_app_build: true`
를 넣자 앱 빌드는 건너뛰었지만 **실패가 더 안쪽으로 옮겨갔습니다** — 그 설정은
`app_location` 을 가공 없이 그대로 올리는데, 배포 로그의 실행 순서를 보면 그 시점엔
API 빌드가 이미 `api/node_modules`(1만 870 개 파일)를 작업 폴더에 만들어둔 뒤입니다.
정적 콘텐츠가 50 개 파일에서 1 만 개로 불어나면서 `Failure during content distribution`
이 됐습니다.

**실패 지점의 소요 시간이 원인이 둘이라는 걸 알려줬습니다.** 2 초·4 초 → 37 초·37 초.
앞의 벽은 넘었고 다른 데서 새로 막혔다는 뜻입니다. 이걸 놓치면 하나의 원인을 계속
파게 됩니다. 그 사이에 끼어 있던 `Node 20 is deprecated` 경고를 원인으로 오해해
`apiRuntime` 을 22 로 올린 커밋이 하나 있는데, 실패 지점이 1 초도 안 움직였습니다 —
**경고는 원인이 아닙니다.**

고친 방법은 마지막으로 성공한 커밋과의 차이를 지우는 것이었습니다. 차이가 딱 둘
(루트 lock 파일, `skip_app_build`)이었고 둘 다 되돌리니 통과했습니다. 원인을 완전히
몰라도 성공한 상태가 남아 있으면 복구할 수 있습니다. `.gitignore` 에 루트만 막는
`/package-lock.json` 을 넣어 재발을 막았고, 워크플로에는 `skip_app_build` 를 켜면 안
되는 이유를 주석으로 남겼습니다.

전부 회귀 테스트를 붙여서 같은 실수가 CI에서 막힙니다.

**화면을 안 보면 못 잡는 부류가 따로 있습니다.** 위 다섯 개는 API가 전부 정상 응답했고
테스트도 전부 초록이었습니다. 숫자로 확인한 검사 세 개가 헛돌기도 했습니다 —
`el.getClientRects().length`는 블록 요소면 항상 1이고, 다크 CSS 블록을 찾던 정규식은
닫는 `}`가 들여쓰기돼 있어 빈 문자열을 검사하고 있었습니다. 스크린샷과 실제 대비값
측정으로만 드러났습니다.

### 다크 모드

`theme.js`가 첫 그림 전에 저장된 설정을 적용합니다. 저장값이 없으면 `data-theme`을
아예 안 붙여서 기기 설정(`prefers-color-scheme`)이 이깁니다.

강조색은 초록을 빼고 **흑백**으로 갔습니다 (`--primary: #f2f2f2` / `--on-primary: #101010`).
검은 배경에서 Discovery Teal이 탁하게 보였습니다. 밝은 모드는 그대로 초록입니다.

측정값: 본문 17.00:1, 보조 텍스트 6.76:1 — 밝은 모드(15.66:1 / 5.42:1)와 함께 AA 통과.

### 시각 표기

시뮬레이션 무대는 밝기 모드와 무관하게 어둡습니다. 관측 대상(추·줄·자석)만 밝게
남겨야 눈이 거기로 가고, 옆 패널의 숫자와 시선이 섞이지 않습니다.

### 시간 표기

모든 날짜·시각은 보는 사람 기기의 시계를 따릅니다. 서버는 UTC로 저장하고,
`session.js`의 `shortDate` / `shortWhen`이 그리는 시점에 지역 시간으로 바꿉니다.
API 테스트는 `process.env.TZ = 'UTC'`로 고정합니다 — 한국 시간대 노트북에서만
통과하는 테스트는 통과한 게 아닙니다.

   페이지를 사람이 읽어야 하는 수준입니다

### 결정된 것 (다시 꺼내지 말 것)

**시뮬레이션 카드 미리보기 색 → 그대로 둔다.** 다크에서 파스텔 블록이 튀는 것은
감수하기로 했습니다. 밝은 모드 기준으로 정한 색을 건드리지 않습니다.

**시뮬레이션 목록으로 가는 길 → 네비에서 바로 간다.** 한때 물리학 드롭다운 안에
링크 한 줄로 넣었다가, 그 뒤 "목록은 안 쓴다" 며 링크를 빼고 검사까지 걸어
막아 놓았습니다. 지금은 **네비 최상위 「시뮬레이션」 자체가 목록으로 가는
링크**입니다. hover·focus 로는 과목별 드롭다운이 열리고, 클릭하면 목록입니다.

드롭다운이 **26개 파일**에 복제돼 있습니다(`Index.html`, `community.html`,
`guide.html`, `post.html`, `simulation/*.html` 21개). 링크 한 줄에 26곳을
고쳐야 하고, 데스크톱만 고치면 모바일 메뉴와 갈라집니다 — 실제로 갈라진 적이
있어서 지금은 페이지마다 개수를 세는 검사가 있습니다. 메뉴를 또 크게 건드릴
일이 생기면 그때는 공통 파일로 빼는 게 맞습니다.

관리자 회원 목록은 걷어냈습니다. 유일하게 남은 목업이었고, 회원 정보를 모아두는
화면은 실제로 필요할 때 만드는 게 낫습니다 — 지금 필요한 조치(제재·차단)는
전부 신고·소명 화면에서 됩니다. 다만 그 화면이 기다렸던 선행 조건(로그인 시
사용자 문서 저장)은 `/settings` 작업으로 채워졌으니, 다시 만들 땐 실제 데이터로
만들 수 있습니다.

**표시 이름을 바꾸면 이미 쓴 글·답변의 작성자명도 함께 바뀝니다.** 이름을 바꾸는
